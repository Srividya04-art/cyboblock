# CyboSocks Turtle Block Editor & Java Runner

A child-friendly block-based programming editor built with React and Blockly, together with a Java console runner that executes the generated program JSON.

## Project Structure

```text
cyboblock/
├── web/       # Part A - React + Blockly editor
├── runner/    # Part B - Java program runner
├── README.md
└── .gitignore
```
## How It Works

The project follows this flow:

Blockly Blocks
      ↓
Generated JSON
      ↓
Copy JSON
      ↓
runner/program.json
      ↓
Java Runner
      ↓
Turtle Execution
      ↓
Console Output

## Part A — React Block Editor

The web application provides four custom Blockly blocks:

1. MOVE — moves the turtle by a specified number of steps
2. TURN — turns the turtle left or right
3. SAY — displays a message
4. REPEAT — repeats a group of blocks

The REPEAT block supports nested repeat blocks to any depth.

The generated program is displayed as JSON in a live panel, with a button to copy the JSON.

### Technologies:

1. React
2. Vite
3. Blockly
4. React Hooks

### RUN Part A

Open a terminal in the project root and run:
1. cd web
2. npm.cmd install
3. npm.cmd run dev

Then open the local URL shown by Vite, for example:
http://localhost:5173/

## Part B — Java Runner

The Java application reads the JSON generated by the React editor and executes the program using a turtle model.

The turtle starts at:
(0, 0)
facing:
North

1. Movement uses:

1. North → positive Y
2. East → positive X
3. South → negative Y
4. West → negative X

A turn changes the direction by 90 degrees.

Nested REPEAT blocks are executed recursively.

### Technologies:

1. Java 17
2. Maven
3. Gson

### RUN Part B

Open a terminal in the project root and run:

1. cd runner
2. mvn clean package

Then run the executable JAR using the JSON file:

1. java -jar target/turtle-runner-1.0-SNAPSHOT.jar program.json

The program.json file can contain the JSON generated by the React editor.

### JSON Format

The React editor generates JSON in this format:

{
  "program": [
    {
      "type": "move",
      "steps": 3
    },
    {
      "type": "turn",
      "direction": "right"
    },
    {
      "type": "say",
      "text": "Hello"
    },
    {
      "type": "repeat",
      "times": 2,
      "body": [
        {
          "type": "move",
          "steps": 2
        }
      ]
    }
  ]
}

Nested repeat blocks are represented by another body array inside a repeat block.

## Error Handling

The Java runner validates input and reports invalid input without printing a stack trace.

The following cases are handled:

Unknown block types
Missing parameters
Invalid turn directions
Negative repeat values
Missing repeat bodies
Malformed JSON

Examples:

Error: Unknown block type: jump
Error: Missing steps parameter.
Error: Repeat times cannot be negative.
Error: Malformed JSON.

## One AI Mistake

During development, an initial misunderstanding occurred around how nested Blockly blocks should be arranged. The first test placed repeat blocks next to each other, which resulted in separate repeat blocks with empty body arrays instead of nested JSON.

I noticed this by comparing the generated JSON with the required nested structure. I fixed it by physically connecting the inner blocks inside the REPEAT block and using recursive traversal of the Blockly statement input.

## One Uncertain Decision

One design decision was how to package the Java application so that it could be executed using a single java -jar command while still including the Gson dependency.

I chose to use the Maven Shade Plugin to create an executable JAR containing the required dependency. If I had more time, I would further test the packaged JAR on another machine with a clean Java installation to confirm portability.
